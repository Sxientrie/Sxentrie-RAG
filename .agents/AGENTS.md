# Project Rules

## Committing Rules
- **Commit Messages**: Always write clear, specific, and concise commit messages that describe the actual changes made (e.g., `fix: add postMessage guard, secure API endpoints, optimize thought stream parser`).
- **Style**: Avoid generic, process-oriented, or "corporate" messages (such as referencing a critique, review, or audit phase). Describe the *what* and *why* of the actual code changes.
